- Coupons: server-only DB function lowers unpaid order item amounts pre-checkout, so checkout math stays order-derived.
- Auction-ending alerts claim a dedupe row before notifying so retries never double-send.
- Shopify Bazaar items: a server-only Storefront sync (scheduled route + bazaar_apply_shopify_sync) owns stock, $3-floor prices and publish/unpublish; checkout rechecks live Shopify stock/price and routes orders to manual fulfillment, never CJ.
- Shopify Bazaar shipping is quoted live from the Shopify Storefront cart (deferred carrier rates) for all Shopify lines together at checkout; CJ shipping stays built into CJ prices.
- PB Trade changes go only through caller-derived, row-locked database RPCs (staff via a separate role-checked RPC), so browsers can't bypass two-sided consent.
- Listing boosts are created only by limit-enforcing DB functions, paid ones activate only from verified payment, and a shared interleave helper caps sponsored feed share.
- Posts/Stories soft-delete only via owner RPCs; staff-only retained-content server fns audit every view/action, and admin restore is owner-only so nothing reappears publicly.
- Marketplace listings may enable Buy Now/Offer/Auction/Trade together; database triggers and accept_listing_offer close the listing for the first winner and refuse later bids, offers and orders, so the UI never decides who won.
- Listing photos (2–10) live in product_details.photos; image_url/back_image_url mirror the first two so legacy readers work.
- Grading submissions are never verification evidence; authenticated server provider lookups alone return confirmed status, without claiming certificate ownership or changing Vault records.
- Seller and admin stream ending shares an authenticated server handler that disables the provider input without deleting recordings, retains transaction history and makes session closure retry-safe.
- Fee policy: Marketplace+Live buyer fees and commission come only from src/lib/feePolicy.ts (Live fees are per stream transaction and apportioned across its orders; Marketplace fee once per checkout, stamped on the first order); PB Store/Bazaar excluded.
- Weekly commission comes from the row-locked, order-idempotent allocate_seller_weekly_commission (sandbox uses a read-only estimate); VIP eligibility is a separate delivery-verified snapshot per original payment week (14-day window), and credits/adjustments are append-only with no automatic refund reversals.
- Accepted Marketplace offers become one unpaid order at the offer price (prepareAcceptedOfferOrder) paid through normal Marketplace checkout, so commission uses the same reserve→confirm allocator; live-show offers refuse charging in preview because they use the live key.
- scripts/commission-isolated/run.sh exercises the real 0062 allocator SQL on a throwaway local Postgres, so commission evidence never writes to the shared database.
- Unpaid commission holds are released on order delete, failure/expiry, or after 30 minutes unpaid (checked inside the allocator before tier choice); a late payment re-counts at the commission already charged. Verify with scripts/commission-isolated/stale.sh.
