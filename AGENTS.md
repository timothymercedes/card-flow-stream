# Project rules

- Share identity-log search validation and shortcut helpers between the audit and detail pages so return navigation preserves the same fingerprint, acting-user, and time filters.
- Admin's parent route always renders Outlet and renders the dashboard only for its exact match so admin tools can display their own screens.
- Use optional search schemas for optional navigation filters so existing links need no invented search values.
- Store single-use passkey challenges in a service-only database table bound to origin, purpose, expiry, and registration owner; workers do not share memory.
- Return web OAuth to the public origin and preserve the sanitized destination separately until the auth server validates the session.
- Keep app email sends in their feature server handlers through the managed template helper; retained email tables are notification history, never send gates.
- Deduplicate terminal email history by a deterministic event ID so signed webhook retries remain safe without changing retained table schemas.
- Managed Stripe notifications use /api/public/payments/webhook with signed environment selection; sandbox notifications never mutate shared production orders.
- Checkout verification uses admin-gated embedded sandbox sessions and server-verified account ownership on the return page; never infer payment success from URL flags.
- Marketplace checkout uses embedded gateway sessions with explicit environment selection and database-derived totals; sandbox sessions omit seller transfers and never stamp production order payment fields.
- Preview must reject seller withdrawal requests and live Connect account changes before side effects; all signed Stripe event processors ignore non-live events because preview shares production balances.
- Marketplace payment regression checks run real sandbox Embedded Checkout through the cart, verify Stripe intents/charges and signed notifications, and clean up only their own unpaid fixtures.
- Target Model A uses Separate Charges and Transfers with environment-scoped seller accounting; keep the existing production charge model until an explicitly approved cutover, because legacy destination charges must never be transferred again.
- Keep unapproved financial release candidates and tests outside application imports and migration directories so review preparation cannot alter production behavior.
- Expose guest auction queues only through the read-only public projection RPC; preserve base-table policies so seller and transaction details remain protected.
- Keep marketplace departments separate from legacy collectible category keys and store general attributes on shared listings; this preserves scanner/Vault compatibility and existing orders.
- Public marketplace search uses a bounded safe-column projection shared by Marketplace, Discover and category shopping; this prevents seller-profile leakage and divergent publication rules.
- Dedicated department shopping URLs use shared configuration and public projection reads, not separate inventories; category keys and collectible subcategories remain distinct.
- Router factories own the per-request QueryClient and SSR query hydration, and the root uses that client; this keeps loader priming and component subscriptions consistent without cross-user caches.
- PB Bazaar uses its own store/product/variant tables with database-enforced store review; never reuse Marketplace listings or PB Store products, so retail inventory and permissions stay isolated.
