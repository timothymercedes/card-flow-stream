## Exact release work packages

1. Capture column-level INSERT/UPDATE grants, RLS policies and trigger call graph for the above tables; enumerate every repo/browser/RPC/retained deployed edge/cron caller. Record exact signatures and expected roles. Existing function JSON is an evidence baseline, not proof of current deployment.
2. Revise existing security SQL with column allowlists/RLS and fail-closed trigger gates; service authority must come from trusted role/context. Avoid user-settable GUC flags, header claims, auth metadata or arbitrary seller IDs as bypasses. Nested definer helpers stay callable only through audited roots; don't break authenticated trigger chains with a blanket service JWT guard.
3. Server handlers authenticate first, verify owner/participant/admin role through user-scoped access, then dynamically import privileged client. Public callbacks verify signature/freshness before privilege. Each operation validates transition, amount, ownership, environment and evidence; serializable safe errors surface failures, not apparent success.
4. Adapt every affected browser/server caller in the same release; service-only shipping adjustment signature must not rely on auth.uid inside an admin-client call. Owner/admin workflows require explicit wrappers rather than broadly executable financial RPCs.
5. Verify secure Shippo timestamp.body HMAC provisioning; implement durable dedupe/retry/binding. Approval to deploy carrier verification is separate from permission to release seller funds. Pickup/freight/vehicle receipts require the reviewed evidence contracts, never reuse an AI scan as delivery proof.
6. Add role/session, direct table, indirect trigger, cross-seller, null-uid, concurrent request and compatibility tests. Map each inventory finding to patch hunk, caller, test and rollback. No finding marked fixed from a specification or parser result alone.

## Release acceptance / no-go

All 25 high-priority inventory cases mapped, all companion table gates included, all callers enumerated, exact SQL and server diff reviewed, isolated application execution and regression passing, deployment order compatible and rollback evaluated. No live testing of exploits. No standalone grant revoke before callers are ready; no loosening rights to repair breakage. Rollback stops operations rather than restoring exploitable financial access automatically. This document prepares the complete scope; the executable patch and isolated validation remain pending approval.
